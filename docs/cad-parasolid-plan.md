# Предпросмотр Parasolid XT в Consysto Files

Дата исследования: 7 октября 2026 года

## Вывод

Файлы Parasolid стоит добавить в список целевых CAD-форматов, но полноценный предпросмотр нельзя честно включить одной строкой с расширением.

В текущем коде Consysto Files:

- `CadMeshSource` запускает `cadmpeg.exe` во внешнем процессе и умеет получать сетку из SolidWorks, NX, CATIA, Rhino, FreeCAD и других форматов;
- список расширений `CadMeshSource` не содержит `.x_t`, `.x_b`, `.xmt_txt` и `.xmt_bin`;
- `StepMeshSource` использует собранный Open CASCADE только для STEP/IGES;
- в поставляемом наборе OCCT нет Parasolid Import Component (нет `TKXSDRAWXT`, `TKDEPARASOLID` или аналогичного модуля).

Поэтому сейчас добавление расширений в список без движка создало бы видимость поддержки: Files принимал бы файл, но получал бы пустую сетку. Такое изменение не включается.

## Что такое Parasolid XT

Parasolid XT — опубликованный Siemens формат передачи B-Rep-моделей. На практике встречаются:

| Расширение | Представление |
|---|---|
| `.x_t` | текстовый XT |
| `.x_b` | бинарный XT |
| `.xmt_txt` | старое/альтернативное имя текстового XT |
| `.xmt_bin` | старое/альтернативное имя бинарного XT |

В файле хранятся геометрия, топология и, в зависимости от экспортёра, цвета, имена и структура сборки. Стандартной встроенной картинки, на которую можно безопасно переключиться, у XT нет. Для предпросмотра нужно реально прочитать B-Rep и выполнить триангуляцию.

Источники:

- [Siemens: Parasolid](https://www.siemens.com/en-us/products/plm-components/parasolid/)
- [Siemens: Data Access and Translation](https://www.siemens.com/en-us/products/plm-components/parasolid/data-access-translation/)
- [Open CASCADE: Parasolid Interface](https://github.com/Open-Cascade-SAS/OCCT-Components/blob/main/Exchange/Parasolid_Import/Documentation/parasolid_interface.md)

## Проверенные варианты движка

### 1. Open CASCADE Parasolid Import Component

У Open CASCADE есть интерфейс `XtControl_Reader`/`XtCAFControl_Reader`, который читает X_T и X_B, переводит геометрию в OCCT B-Rep и может передавать цвета, имена и сборки.

Это не обычный открытый модуль OCCT: Parasolid Import относится к коммерческим компонентам Open CASCADE. Текущая бесплатная сборка OCCT в проекте содержит STEP/IGES, но не этот импортёр.

Плюсы:

- наиболее естественно ложится на существующий `Consysto.StepMesher`;
- можно оставить тот же протокол «файл на входе — `.csmesh` на выходе»;
- не требуется SolidWorks, КОМПАС или NX на машине пользователя;
- можно сохранять структуру сборки и цвета на следующем этапе.

Минусы:

- нужна отдельная лицензия и разрешение на распространение DLL;
- придётся проверять совместимость с актуальными схемами Parasolid;
- увеличится размер портативной сборки;
- нельзя добавлять бинарники в публичную ветку без проверки условий лицензии.

### 2. Parasolid Communicator / HOOPS Exchange

Это коммерческие SDK от Siemens и Tech Soft 3D. Они рассчитаны именно на встраивание в приложения и дают чтение, запросы свойств и триангуляцию.

Плюсы:

- зрелый промышленный путь;
- лучшее покрытие версий и сборок;
- есть официальная поддержка.

Минусы:

- платная лицензия;
- условия распространения нужно согласовать до публикации бесплатного Files;
- существенно увеличатся стоимость сопровождения и размер пакета.

### 3. CAD Assistant

CAD Assistant от Open CASCADE действительно открывает XT на Windows и умеет показывать модель. На странице продукта прямо указано, что импорт Parasolid предоставляется коммерческим компонентом, а экспорт/конвертация таких импортов отключены.

Это хороший способ вручную проверить пользовательский файл, но плохая архитектура для Files:

- это отдельное GUI-приложение, а не стабильный headless API;
- Files пришлось бы зависеть от установленной внешней программы;
- автоматическое управление окном и снятие картинки ненадёжны;
- нельзя считать наличие CAD Assistant частью портативной поставки без отдельной проверки лицензии.

Использовать CAD Assistant как обязательную зависимость не рекомендуется.

### 4. parasolid-kit

Проект [monozukuri-ai/parasolid-kit](https://github.com/monozukuri-ai/parasolid-kit) — открытый парсер X_T/X_B с лицензией MIT и Apache-2.0. У него есть Rust-ядро, профили схем и необязательный конвертер через Python/OCP.

Это интересный исследовательский вариант, но не готовая замена промышленному импортёру:

- встроенные профили покрывают ограниченный набор схем и проверенных подмножеств;
- для других схем нужны отдельные каталоги схем;
- для триангуляции на Windows нужен профиль OCCT и Python-runtime;
- размер и состав такого runtime нужно отдельно измерять;
- проект прямо разделяет «файл распарсен» и «получена полная геометрия», поэтому успешное чтение заголовка не означает готовый предпросмотр.

Его можно использовать для отдельного экспериментального helper-а, но только после теста на реальных X_T из SolidWorks, NX и других Parasolid-экспортёров.

### 5. Самостоятельный разбор X_T

Писать собственный универсальный импортёр нецелесообразно. Формат опубликован, но запись зависит от схемы Parasolid, а B-Rep включает поверхности, кривые, топологию, указатели и NURBS. Ошибка в одном поле может испортить весь поток. Для предпросмотра это слишком большой объём геометрического кода и тестовых данных.

## Рекомендуемая механика для Files

### Этап A. Контракт движка

Вынести чтение «чужих» CAD в отдельный контракт:

```text
input file
  -> isolated CAD provider
  -> bounded mesh result (.csmesh)
  -> Files 3D preview
```

Провайдер не должен получать команды из содержимого файла. Files передаёт ему только проверенный абсолютный путь и случайный путь результата.

Минимальный контракт:

- вход: путь к исходному файлу, формат и версия протокола;
- выход: бинарный `.csmesh`, код результата, диагностический текст;
- stdout/stderr не используются как данные модели;
- провайдер не должен менять исходный файл.

### Этап B. Изолированный Parasolid helper

После выбора лицензированного или открытого движка добавить отдельный `parasolid-mesher.exe` рядом с `cadmpeg.exe` и `Consysto.StepMesher.exe`.

Рекомендуемый режим:

1. проверить расширение и размер до запуска;
2. создать временную рабочую папку с непредсказуемым именем;
3. запустить helper без shell и без передачи командной строки из файла;
4. ограничить время, дерево процессов и максимальный размер результата;
5. проверить заголовок `CSMESH1`, число треугольников, диапазоны координат и конечный размер;
6. удалить временные файлы после чтения, оставив только кэш с ключом размера/времени/версии;
7. при любой ошибке вернуть обычное состояние «предпросмотр недоступен», не падать и не запускать другой файл.

Для X_T желательно ограничить размер текстового потока и число сущностей ещё до полной геометрической конвертации. Для X_B ограничения должны быть на уровне reader/helper, а не только на уровне Files.

### Этап C. Поддержка расширений

Расширения добавляются в пользовательский список только одновременно с работающим provider:

- `.x_t`;
- `.x_b`;
- `.xmt_txt`;
- `.xmt_bin`.

Если provider отсутствует, Files не должен показывать эти форматы как успешно поддержанные. Допустимое поведение — обычный CAD-значок и сообщение «Для 3D-предпросмотра не установлен Parasolid engine».

### Этап D. Тестовая матрица

До публикации нужны реальные файлы с разрешением на тестирование:

1. простой SolidWorks X_T;
2. простой NX/Parasolid X_T;
3. X_B;
4. многотельная деталь;
5. сборка с цветами и именами;
6. несколько версий Parasolid;
7. файл с открытой оболочкой;
8. повреждённый/обрезанный X_T;
9. искусственно большой файл для проверки лимитов;
10. файл с необычными единицами.

Для каждого файла фиксируются:

- успешно ли прочитан заголовок;
- число тел/корней;
- получена ли полная сетка;
- габариты и единицы;
- число треугольников;
- время и пиковое потребление памяти;
- поведение при отмене и тайм-ауте.

Нельзя считать один удачный куб доказательством поддержки всех версий XT.

## Безопасность

Риск здесь не в «скриптах внутри X_T»: сам XT не должен исполняться. Риск — в уязвимости или зависании импортёра на специально подготовленных данных.

Обязательные меры:

- отдельный процесс;
- `UseShellExecute=false`;
- только аргументы, сформированные Files;
- тайм-аут и уничтожение всего дерева процессов;
- ограничение исходного файла, результата и числа треугольников;
- запрет записи вне временной папки и кэша;
- проверка бинарного результата до передачи в WinUI;
- отсутствие загрузки DLL из каталога исходного файла;
- проверка SHA-256 helper-а при сборке;
- лицензии и notices рядом с helper-ом;
- не показывать пользователю диагностический текст, взятый из файла, как разметку или команду.

## Решение для текущей ветки

Сейчас разумно оставить код без ложной поддержки `.x_t/.x_b`. Следующий рабочий шаг — собрать изолированный прототип одного provider-а и измерить:

- реально покрываемые версии;
- размер поставки;
- время предпросмотра;
- память;
- ограничения лицензии.

После этого можно выбрать один из двух честных вариантов:

1. **промышленный выпуск:** лицензированный OCCT Parasolid Import или HOOPS/Communicator;
2. **экспериментальный выпуск:** отдельный необязательный `parasolid-kit` helper с явно ограниченным списком проверенных схем.

До выбора движка добавлять расширения в `CadMeshSource` нельзя: это даст пустое превью и будет выглядеть как готовая функция.

## Практическая проверка открытого кандидата

7 октября 2026 года был проверен `parasolid-kit` 0.3.7 в отдельном каталоге Windows. Для теста взят публичный текстовый X_T-куб из [публичного gist](https://gist.github.com/MattFerraro/57e5dc45fa10d71c28eb5078ad65626a), SHA-256 файла:

`bb9c15ee54e6ee8e5cd2e9159c00b72d80fe8d0b4165384301354b3e00f4bd70`

Результат:

- `inspect` успешно распознал текстовый XT, версию моделлера `3401198` и схему `SCH_3001000_30100`;
- `check` остановился до построения B-Rep: встроенного профиля для этой схемы нет, требуется внешний каталог схем;
- установленный Windows-профиль OCCT занял около 47 МБ в виде wheel, сам parser — около 1,2 МБ, но готового универсального конвертера для произвольных X_T это не даёт.

Это полезный результат для архитектуры: открытый parser годится как экспериментальный provider, но его нельзя объявлять универсальной поддержкой `.x_t` без поставляемых и юридически проверенных каталогов схем и набора реальных образцов.

## Сравнение бесплатных parasolid-kit и ps-parser — 7 октября 2026

### Решение

Для исследования автономного предпросмотра выбран **parasolid-kit**. Код разрешено использовать и распространять бесплатно при соблюдении MIT и Apache-2.0; готовая цепочка преобразования через свободное ядро OCCT уже существует. Это выбор основы для эксперимента, а не подтверждение поддержки произвольного X_T в Files.

**ps-parser** также имеет разрешительную MIT-лицензию, но в проверенной версии не решает задачу предпросмотра: он читает бинарные X_B и возвращает записи/дерево связей. Чтение текстового X_T и создание сетки потребовали бы дополнительной разработки. Бесплатность самого Files не освобождает от условий лицензий зависимостей. Назначение «только предпросмотр» также не даёт исключения из лицензии коммерческого SDK.

Исследование не меняет CAD-провайдеры или установленную/портативную сборку Files.

### Что проверено в исходниках и лицензиях

| Критерий | parasolid-kit | ps-parser |
|---|---|---|
| Проверенная версия | Python package 0.3.7; исходники `2bc959687c8ca87145c4e0594828c3fa11aab912` | `887f7b3be1e500d79583c133129b5d845cc1498c` |
| Лицензия кода | `MIT AND Apache-2.0`, требуется соблюдать обе | MIT |
| Текстовый X_T | Поддерживаемые точные ключи схем; другие — внешний каталог | Reader явно отвергает текст и принимает только `PS` binary |
| Бинарный X_B | Есть | Есть |
| Путь к сетке | `read_brep → to_occt → tessellate_preview` | Нет готового преобразования записей в поверхность/сетку |
| CAD-программа у пользователя | Не нужна для встроенных профилей | Программа не нужна, но нужен каталог схем |
| Расширение покрытия | Точный внешний каталог или разработка встроенного профиля | Базовый каталог плюс встроенные в файл изменения схем |
| Лимиты | `ParseLimits` и отдельные `InteropLimits` | В проверенной версии аналогичных общих бюджетов нет |

Источники лицензирования и технических ограничений:

- [parasolid-kit: пакет и состав лицензий](https://github.com/monozukuri-ai/parasolid-kit/blob/main/pyproject.toml), [MIT](https://github.com/monozukuri-ai/parasolid-kit/blob/main/LICENSE), [происхождение Apache-компонентов](https://github.com/monozukuri-ai/parasolid-kit/blob/main/crates/parasolid-core/PARTIAL_READERS.md).
- [parasolid-kit: поддерживаемые схемы и геометрия](https://github.com/monozukuri-ai/parasolid-kit/blob/main/docs/format-support.md), [правила внешних каталогов](https://github.com/monozukuri-ai/parasolid-kit/blob/main/docs/schema-catalogs.md).
- [ps-parser: возможности](https://github.com/khoanguyen-3fc/ps-parser), [MIT](https://github.com/khoanguyen-3fc/ps-parser/blob/main/LICENSE).

MIT/Apache требуют сохранить тексты лицензий, сведения об авторах и применимые уведомления; изменения заимствованных Apache-файлов следует обозначать. Их условия допускают бесплатные и платные приложения: стоимость Files здесь не является критерием.

OCP wrapper в установленном Windows-пакете объявляет Apache-2.0. Само ядро OCCT распространяется по LGPL-2.1 с исключением. При подготовке пакета нужны также лицензии OCCT, доступ к соответствующим исходникам, соблюдение условий замены/перелинковки и уведомления всех фактически включённых библиотек. Метаданные Python wheel не заменяют проверку лицензий находящихся внутри него DLL.

Источники: [OCCT LGPL](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/LICENSE_LGPL_21.txt), [исключение OCCT](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/OCCT_LGPL_EXCEPTION.txt).

### Каталоги схем и распространение

Здесь нужно различать сведения об устройстве формата, самостоятельно написанные описания записей и конкретные готовые файлы каталога производителя. Исследование не установило, что за любое описание схемы XT требуется отдельная платная лицензия Siemens. Оговорка относится к правам на распространение конкретного стороннего файла, а не к запрету независимого анализа или открытой реализации читателя.

Встроенные профили parasolid-kit входят в открытый исходный код; штатный путь не требует копирования каталога из установленного SolidWorks/NX. Поддержка ограничена точными ключами и типами записей — похожее имя версии не позволяет подменять профиль.

По документации происхождения проекта, профили создавались по опубликованной XT Format Reference и анализу экспортированных моделей. Для ранних V30-профилей каталоги Siemens не использовались для генерации определений; более поздние ревизии также документируют сравнения/аудиты с каталогами. Это заявление разработчиков о происхождении, а не проведённая нами независимая проверка истории всех определений. [Описание метода](https://github.com/monozukuri-ai/parasolid-kit/blob/main/docs/builtin-profiles.md).

В ps-parser есть `assets/sch_13006.s_t`. Его заголовок описывает исторический каталог Parasolid, созданный в 2001 году. MIT-лицензия репозитория сама по себе не доказывает полномочия автора предоставлять права на отдельный сторонний каталог. Самостоятельное разрешение на распространение этого файла в Files в ходе исследования не подтверждено. Это вопрос комплектования публичного пакета, а не заявление о нарушении со стороны проекта.

Этот каталог использован только в локальном диагностическом опыте и не добавлен в репозиторий или сборку Files. Внешние каталоги нельзя автоматически брать из пользовательской CAD-установки и включать в публичный выпуск.

### Практические результаты на Windows

Использованы опубликованный parasolid-kit 0.3.7, `cadquery-ocp-novtk` 7.9.3.1.1 и Python. Каждый замер ниже выполнен в отдельном процессе; измерено время работы после импорта основных API, включая холодную загрузку OCCT внутри операции. Память — PeakWorkingSet процесса, а не объём только геометрии. Это небольшие контрольные опыты, не нагрузочный тест и не матрица совместимости.

| Опыт | Результат |
|---|---|
| parasolid-kit: синтетические X_T и X_B, одна запись целых чисел | Оба прочитаны без внешнего каталога; геометрии в этих пробах нет |
| ps-parser: синтетический X_B с базой 13006 и одной записью | Прочитан; получены два целых значения; геометрии в пробе нет |
| ps-parser: публичный текстовый X_T | Отказ `only PS binary format is supported` |
| parasolid-kit: независимый публичный Onshape-куб | Штатный путь: `schema.missing_base_schema`, ключ `SCH_3001000_30100` |
| parasolid-kit: независимый публичный FHMP-6-ABL.x_t, 8 878 129 байт | Штатный путь: `schema.missing_base_schema`, ключ `SCH_2901259_28101_13006` |

Независимые образцы:

- [Onshape-куб](https://gist.github.com/MattFerraro/57e5dc45fa10d71c28eb5078ad65626a): SHA-256 указан выше.
- [FHMP-6-ABL.x_t, публичный образец CAD-Extractor](https://github.com/mayankmmmx/CAD-Extractor/blob/main/FHMP-6-ABL.x_t). Его доступность для исследования не означает право включить файл в наш публичный тестовый пакет.

Отдельно проверена стадия **B-Rep → OCCT → сетка** на четырёх подготовленных моделях из открытых тестовых fixtures проекта. Эти модели созданы непосредственно в памяти; X_T-файл в этих опытах не читался. Поэтому успешный GLB не доказывает успешность всей цепочки от реального файла.

Грубая сетка отверстия: linear deflection 0,5 мм, angular deflection 0,8 рад; более подробная: 0,05 мм и 0,2 рад. Рёбра в GLB отключены. Проверены числовые результаты и успешное создание GLB; проверка этих моделей в интерфейсе Files не выполнялась. Большая часть времени и памяти малого опыта приходится на загрузку runtime, поэтому снижение детализации здесь почти не уменьшило время запуска.

Размер установленного runtime в эксперименте, без Python, pip и тестовых зависимостей:

- parasolid-kit: **4,43 МиБ**;
- OCP без VTK: **153,16 МиБ**;
- proxy: **0,01 МиБ**;
- сумма: **157,60 МиБ** до упаковки.

Это не прирост финального ZIP Files. Готового автономного пакета нет; размер Python-runtime, сжатие и возможное использование уже поставляемого OCCT требуют отдельной проверки. Предыдущие примерно 47 МБ описывали скачанный wheel, а не распакованные библиотеки. Уменьшение точности сетки не уменьшает размер DLL.

### Что означает «нам нужен только предпросмотр»

Можно исключить историю операций, точные измерения, редактирование и сохранение CAD-модели. Можно уменьшить число треугольников и показывать частичную геометрию с явным предупреждением.

Но остаются обязательными чтение схемы, расположение и ориентация граней, границы отверстий и корректная связь поверхностей с контурами. Снижение точности триангуляции не исправляет неизвестную схему или неподдерживаемую поверхность. Частичное превью должно показывать реально восстановленные части, а не правдоподобную выдуманную форму.

### Практический путь интеграции после исследования

1. Использовать parasolid-kit как необязательный экспериментальный provider с зафиксированной версией и только поддерживаемыми встроенными профилями; внешние каталоги не включать до подтверждения прав.
2. Получить самостоятельные CAD-образцы с точными поддерживаемыми ключами и правами на тестирование. Проверить всю цепочку «исходный X_T/X_B → сетка → изображение», отдельно для отверстий, NURBS и нескольких тел. Сейчас ни один из двух независимых X_T не дал готовую сетку.
3. На прототипе получать только треугольники. Использовать существующий формат Files `CSMESH1\0`: 16 байт заголовка, затем девять little-endian float32 на треугольник. У Files уже есть растеризатор, поэтому веб-просмотрщик parasolid-kit и локальный HTTP-сервер не нужны.
4. Запускать обработчик по явному запросу, с кэшем и ограничением параллелизма. Для начала: один процесс, вход до 32 МиБ, до 100 тыс. треугольников, результат до 8 МиБ, тайм-аут 15 секунд и лимит памяти 512 МиБ. Это предлагаемые бюджеты, ещё не подтверждённые нагрузочными испытаниями.
5. Ограничить процесс средствами ОС: Job Object для памяти/времени/дерева, ограниченный токен или AppContainer для доступа к файлам и сети. Отдельный процесс и `UseShellExecute=false` сами по себе не являются песочницей. DLL загружать только из контролируемого каталога поставки; пользовательский файл не должен определять путь к библиотекам.
6. Проверять размер выходного файла до полной загрузки, сигнатуру, счётчики и конечность всех координат до выделения буферов. Не позволять входным данным задавать имена выходных файлов или команды. Неподдержанный файл должен давать обычное сообщение, а не белое «успешное» превью.
7. После доказательства всей цепочки оценить оптимизацию: Rust parser плюс адаптер к имеющемуся C++ OCCT потенциально устраняет Python и дублирование DLL, но такого готового адаптера в проверенном наборе нет. Это отдельная разработка.

**Итог:** бесплатное использование кода подтверждено у обоих проектов. Для предпросмотра перспективнее parasolid-kit; ps-parser оставить как исследовательский бинарный reader. Готовый бесплатный универсальный provider для Files из этих опытов не получен. Выбор основания для разработки сделан; интеграция и выпуск остаются отдельными задачами.
